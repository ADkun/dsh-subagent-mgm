# dsh-subagent-mgm

DeepSeek Harness Web UI 插件（bundle）：管理子智能体的目录顺序与右侧栏面板，并在子智能体失败时把真实原因交给父智能体。

## 它做什么

1. **子智能体目录按创建时间倒序**。会话顶部「N 个子智能体」的展开菜单里，最新的子智能体排在最上面；展开的每一层下级目录同样按创建时间倒序。行的内容（状态点、标题、模式、活跃耗时、token 数、在侧边栏打开按钮、键盘导航、悬停展开）与原版一致，只改了顺序；每一行右侧的用量读数比原版**多一行缓存命中率**（原版只把它放在悬停提示里；这一行印的是「缓存 84%」，汇总带那一项印的是「缓存命中 87%」，同一个数字、行上少两个字），口径与上方汇总带一致，见第 5 条。点进某个子智能体会话后，会话顶部那枚**面包屑切换器**（列出父会话的兄弟子智能体）同样被接管，也按创建时间倒序；它旁边保留「这个子智能体自己的子目录」计数入口，行为与原版一致。
2. **跟随子智能体自动开合右侧栏面板**。当前屏幕上这个会话有子智能体在运行时，自动在右侧栏打开它的会话；子智能体结束时自动关闭该面板。
   - 结束时的关闭**不限于当前屏幕上的会话**：子智能体在后台会话里结束，也会把它留在这个会话侧边栏里的面板关掉，切回该会话时不会再看到已经结束的子智能体聊天。
   - 已经存在的子智能体被父智能体再次派活（可继续模式）、重新开始工作时同样会自动打开；若它的面板还开在后台标签里，则把它拎到前台并展开右栏，而不是再开一个。
   - 每次运行只自动处理一次：同一个子智能体连续运行期间不会反复把右栏抢回前台，用户可以自己切走；切换会话再回来也不会重新抢。
   - 用户手动提前关闭：该子智能体本次运行期间不会再被自动打开（跨会话切换同样不会），下次重新运行时会恢复自动打开。
   - 用户手动打开：插件不会去关它，除非该子智能体结束。
   - 打开只处理当前会话的**直接**子智能体；面板打开方式是「已在则复用」，不会为每次自动打开强行新建分栏。
3. **设置页**：设置里多一页「子智能体管理」（排在官方插件设置页之后）。五个开关——
   - 子智能体目录/面包屑按创建时间倒序（关掉即回到官方原顺序）；
   - 子智能体开始运行时自动打开右侧栏面板；
   - 子智能体结束时自动关闭该面板；
   - 把已开在后台的面板拎到前台（关掉就完全不抢焦点，只保证面板已存在）；
   - 子智能体失败时，把它自己日志里的停止原因补进给父智能体的那条结束通知（关掉则父智能体只看到官方那句「failed before it finished」）。

   保存会写入本插件的设置文件，可一键恢复默认；刷新后仍然生效，页面上同时显示当前生效值与设置文件路径。
4. **查看某个子智能体「有什么」**。目录里每一行多一个证件卡按钮，点开该行的能力面板（菜单会临时加宽），四段只读信息——
   - **这份工作是什么**：模式（可继续 / 一次性）、此刻是否在运行、唤醒方式、预设、它这一次运行所用的模型与推理档位、工作目录、层级深度、父会话、创建时间，以及委派时设定的**工具过滤**（allow / deny）；
   - **工具**：它在最后一次请求里实际拿到的工具清单与描述，每个工具可展开看它的参数 schema；
   - **SKILL**：这个会话（它的预设 + 工作目录）当前可见的技能清单，并标出哪些是「仅智能体可调用」；宿主没挂技能注册表时会明说，而不是显示成空；**这次委派没把 `skill` 工具给它时，这一段不再列技能，而是直接说明它看不到任何技能**——技能目录只发给手里有 `skill` 工具的智能体，所以「这个会话可见」并不等于「这个子智能体可见」；
   - **人格**：委派记录下来的 persona（权威）；没有记录时，由它的系统提示与**该父会话首次组成时**的系统提示做差分恢复，并注明这是推断；如果恢复到的这一行其实是宿主按运行模型填进人格槽位的，会标注「按运行模型生成」。

   内容全部由宿主只读推导（浏览器读不到别的会话的日志）。面板有返回按钮，Esc 退回目录，加载失败可重试。
5. **在目录里找子智能体，并看清这一屏的用量**。展开菜单顶部多了一行控制条和一条汇总带——
   - **搜索与筛选**：按名字 / 标题 / 工作目录做大小写不敏感的文本匹配，另有「全部 / 已结束 / 仅一次性」两个筛选维度（可叠加）。命中行会连同它的祖先一起显示（祖先只是路径，否则你就看不到它挂在谁下面），并且层级自动展开、不可再折叠；过滤期间展开箭头不再可点，避免「展开了但看不到东西」。什么都没命中时给一句话，而不是一片空白。
   - **汇总**：分两行摆，各自换行也不会互相挤压——上面一行是计数（这一屏**已加载**的行数、其中在运行的个数，以及拿不到投影的「N 个没有用量数据」），下面一行是用量（token 合计、**缓存命中率**、活跃耗时合计，悬停都给精确值）。**当前这一屏的会话自己也算进合计**，并在合计里点名它的份额（「合计 1.2M（本会话 320K）」），悬停给出它自己的缓存读 / 缓存写 / 提示 / 未命中：它不在目录里，所以不算一行、计数不变，但它的 token 和缓存桶和这些子智能体花在同一处。拿不到投影的行不会算成 0。
   - **缓存命中**：命中率 = 缓存读 / 提示侧用量（提示侧用量 = 未缓存输入 + 缓存读 + 缓存写，**输出 token 不算**），与聊天页底部的口径一致。命中不足 100% 时不会四舍五入成 100%（99.99% 就显示 99.99%），悬停给出「缓存读 / 缓存写 / 提示 / 未命中」的精确拆分。整棵树**先按桶求和再取比值**，所以它是「这一屏的真实命中率」，不是各行命中率的平均；没有用量的行不进分母，一行用量都没有时干脆不显示这一项。同一个口径也印在**每一行**上：目录行右侧的用量读数因此是三行——token、活跃耗时、**缓存命中率**（这一行印的是「缓存 84%」，汇总带那一项印的是「缓存命中 87%」——同一个数字，只在行上省掉「命中」二字，免得 336px 的菜单里把行名挤掉；只在该行确有可计费提示用量时才多出这一行，其余行仍是原来的两行、不占多余高度），逐行可读、不必悬停；悬停那一行给出该行「缓存读 / 提示 / 未命中」的精确拆分，与悬浮卡里的逐行命中率用的是同一套数字与文案。
   - **按模型分组**：点一下按钮才去读——模型只写在各自会话的日志里，浏览器拿不到，所以这是一次**按需**的只读批量请求，读完就按模型分好组（每个模型一行：token 合计、该组的缓存命中率、命中行数；由委派指定、还没跑过的行标注出来）。读不到就报错并可重试，不假装成「未知模型」。这一屏的会话自己也在被统计的节点里（它有自己的模型），所以某个模型行末尾的 × 计数把它算作一个。
6. **侧边栏会话行的悬浮摘要**。鼠标停在侧边栏任意会话行上，弹出的卡片里会在官方那行「N 个子智能体运行中」**上方**多出一段摘要——
   - **计数**：这一屏的子智能体数、其中在运行的个数；拿不到投影的按「N 个没有用量数据」另算，不算成 0。
   - **用量**：token 合计（含这个会话自己，并点名它的份额）、缓存命中率、活跃耗时合计。口径与目录里那条汇总带**完全一致**（同一个折算函数，不重新实现一遍），悬停同样给精确值与缓存拆分。
   - **最多 4 个直接子行**：状态点、标题（长了省略）、token、命中率；其余只报个数。卡片是悬浮出来的，不宜长成一棵树。
   - **纯客户端、只读**：只读浏览器已经持有的那两份 store，不读日志、不发请求、不写任何状态；行也不做成按钮——卡片上的点击已经被工作区用来复制会话标题了。
   - **没有子智能体的会话也有内容**：这类会话原来的卡片只有官方的「空闲」一行，现在摘要改报**它自己的**用量——「本会话 320K · 缓存命中 92.3% · 总用时 12m30s」。总用时来自宿主折叠好的 `sessionStats` 投影（模型时间 + 工具时间），与子行那个「工作时间」是同一类数字；三项各自独立，算不出就不显示，全都没有（比如刚建出来还没说过话的会话）则整段不出现，不报 0。
   - **立即弹出、且不会叠着**：鼠标停在会话行上不再等官方那 800ms，卡片马上出现；新卡一弹出，先前那张立刻收掉（不等官方那 200ms 指针宽限），所以连续划过多个标题只会剩最后停下的那张。只划过一行、没有新卡弹出时，移开鼠标后的消失延迟保持原样。

    注意它只列**直接子行**（更深的下级只计入计数），也不做模型分组（模型只在日志里，那要用上面那个按需按钮）。官方那行「N 个子智能体运行中」由工作区自己渲染，插件删不掉它，只是排在它前面。立即弹出是**运行期包住那支开卡定时器**做到的（没改官方文件，也没替换任何导出——原语导出是 shell 冻结的），所以共用那个原语的其他卡片（工作区行、预览卡）同样立即展开；「新卡替掉旧卡」则是在同一处把官方那支 200ms 指针宽限一并接管：只有“旁边又弹出一张卡”时才提前收，单纯把鼠标移开仍是官方那 200ms。

7. **子智能体失败时，把真实原因交给父智能体**。可继续（continuable）模式的子智能体失败时，宿主只给父智能体一句「failed before it finished」，原因（错误码、HTTP 报文）在官方那条通知里根本没有——那条通知只由 `{stopReason, output}` 拼出来，provider 给的失败明细在那条路径上被丢掉了（一次性子智能体不受影响：它的失败原因本来就在父智能体收到的工具结果里）。打开这个开关后，插件在父智能体即将进入的那一步里，从**子智能体自己的日志**读出它最后一轮的 `turn/end` 停止原因，把这行补进同一条通知；父智能体当步就能看见，不必再拿 `send_message` 反复试探一个已经结束的子会话（这正是打开前的实际表现：父智能体连发四次 `send_message` 去问一个已经死掉的子代理，因为它手里只有「failed before it finished」这一句）。补进去的是事实而不是猜测：日志里没有 `turn/end` 就明说「它没跑完任何一轮」，日志不在这个 profile 里就说没有日志，读失败就连读失败的原因一并说明——三种结局都不让父智能体白猜。开关只影响这一条补注，关掉即完全恢复官方原样。

## 实现要点

- 浏览器半边通过 `window.__ModuleLoader__.load({ id: 'dsh-subagent-mgm', factory })` 注册，`exports.inject` 声明所需服务：`sessions`、`uiWorkspace`、`slots`、`locale`、`sidebarRight`。
- 目录：以 list slot 的 shadow 机制（同一 `id`、更低 `priority` 生效）接管 `conversation.session.header.actions` 里的 `subagent-catalog` 座位，复用官方 `@deepseek-ai/dsh-client-ui-subagent` 的标记结构、样式与行为，类名前缀改为 `smgm-`，文案注册在自有命名空间 `subagentMgr`。
- 面包屑：子智能体会话的标题位是 single slot `conversation.session.header.lineage`，官方在这里放的就是那枚兄弟切换器。single slot 没有 `id` 可复用，只能用更低的 `priority: -1` 抢在官方（priority 0）前面，否则进入子智能体后会退回原版顺序。
- 面板：订阅 `ctx.sidebarRight.mounted`、`ctx.sidebarRight.openTabs`、`ctx.sessions.list`、`ctx.uiSession.sessionStatus`，每次变更后先按「`openTabs` 里每个会话的已开标签 ∩ 运行状态」关掉已经结束的子智能体面板（对屏幕上的会话和后台会话一视同仁），再按「当前会话的目录 ∩ 运行状态 ∩ 已打开标签」对账自动打开；标签地址形如 `dsh-resource://subagentchat/session/<child>?parent=<parent>&mode=<mode>`，与官方子智能体聊天资源提供者一致。运行态记录（是否见过它运行、是否被用户手动关过）按子会话 id 全局记账、跨会话切换保留，只有「本次已拎到前台」和投影重试记录会在切换会话时重置。
- 设置页：在官方 `settings.section`（list slot，scope root）注册一页，`id: subagent-mgm`、`order: 37`、`label: () => t('settings.nav')`。开关存在浏览器侧的订阅式 store 里，目录排序和面板对账各自在每次计算时读一次，所以改完立即生效，不需要重启，也不需要刷新页面。
- 宿主半边：用 `ctx.inject(['webServer'], …)` 注册 `prefix` 路由 `/api/subagent-mgm`，其 `/settings` 支持 GET / POST / DELETE；设置写入 `<DSH_PROFILE_DIR|DSH_HOME|~/.dsh>/subagent-mgm.json`（先写临时文件再 rename 原子替换，权限 0600），字段优先级为「已保存文件 → 本行 Config → 内置默认」，行默认值写在本 bundle 的 `cordis.patch.yml`。路由沿用与 connection 服务相同的同源栅栏：没有认证的非浏览器客户端收到 401，跨站 Origin / 伪造 Host 收到 403。
- 能力面板：同一前缀下还有 `/face?sessionId=…&parent=…`（GET，只读）。宿主用 `sessionQuery.readSession` 读该会话的持久日志，折叠出首个 `subagent/descriptor`、**最后一次** `request/header` 的工具与模型、以及人格；技能来自可选的 `sessionSkillCatalog.list`（服务缺失 → `unavailable`，抛错 → `error`，都不影响其余字段）；宿主给的是**这个会话可见的整份目录**，而「是否列给用户看」由客户端按同一次委派的工具面定：`skill` 不在那次工具面里（allow 里没写它、deny 里写了它，或最后一次请求的工具清单里根本没有它）时，这一段只印一句说明、不列技能，于是同一次委派的面目与技能段不会自相矛盾。人格三级来源：descriptor 里的记录（权威）→ 与父会话系统提示做行级差分（公共行前缀 ≤ 2 行才认，因为 persona 槽位紧跟 harness 身份行；恢复到的通常是宿主按模型生成的那一行，用返回体里的 `generated` 标注）→ 都没有就为 `null`。差分只比**双方日志里的第一份**系统提示：会话中途换模型会重写人格槽位，那份晚到的组成与「这次委派给了它什么」无关——真实日志里确实出现过，按最后一份比会凭空造出人格。父会话 id 优先取会话头里的 `parentSession`，前端再把当前打开的会话作为 `parent` 提示兜底（老日志没有该字段时仍能恢复）。客户端只渲染返回体，自己不读日志。
- 过滤与汇总：全部是**客户端行为**，只在这一屏已加载的目录投影上做，不读任何日志、不发任何请求。过滤是每层独立裁剪（子层是自己按 `catalogOf(childId)` 现取的，不是从父层继承），谓词是「自身命中，或任一已加载的后代命中」——所以祖先会作为路径留下，**也计入汇总**：汇总说的是「屏幕上这些行」，因此按「未运行」筛出来的结果里仍可能报 1 行在运行（那是被留下的祖先）。**当前这一屏的会话本身也走同一套记账**（`catalogTotals` 里只有一个内部折算函数，行与它共用，两边不会漂开）：它不占行数，但 token 与缓存桶进合计；去留也由同一个过滤谓词决定，于是「仅一次性」会把它排除（它不是委派），状态筛选只在它自己匹配时留下它，而它一旦被留下就不会再作为行被重复计数（先记进去重集合）。没装宿主新半边时按模型分组会显示读取失败。缓存命中率也在这批行上算（含这一屏会话），但**先按桶求和再取比值**：比例之和 ≠ 比例的平均，逐行算好再相加会让整屏数字和单份日志的口径漂开；没有用量的行不进分母，分母 ≤ 0 时返回 `null`（这一项不显示），部分命中**朝下取整而不是进位到 100%**——99.99% 就是 99.99%。
- 模型批量：`GET /api/subagent-mgm/models?sessionIds=a,b,c`（GET，只读）。每个 id 过一次 `SESSION_ID` 校验、去重、上限 64 条（超了 400），逐 id 读一次 `sessionQuery.readSession` 折叠出「委派指定的 `agentModel`（descriptor）」与「这一轮实际在跑的 `model`（最后一次 `request/header`）」，外加模式与预设。**单条失败只影响那条**：日志不存在 → `state: "missing"`，读失败 → `state: "error"` 带上原因，整批照样 200。客户端按 `totals.nodes` 里出现的 id 发起，拿回来按 sessionId 归档；用户在条上改了筛选后再点一次就重新读。
- 悬浮摘要：占用工作区的 `sidebar.session.row.hover` 座位（list slot、scope root，`id: subagent-digest`、`order: 5`，排在同样占这个座位的官方排程插件 `order: 10` 之前）。座位只把这一行的 `sessionId` 交给占用者，没有 store 可以注入，所以插件在 `ctx.inject(['uiSession'], …)` 里现挂订阅：`sessions.list` 的 `projectionsBySession` / `byId` 与 `uiSession.sessionStatus` 各订阅一次，卸载时一并退订（宿主半边与本插件其余的座位都不受影响）。数字直接复用 `catalogTotals`（`selfId` 就是这一行），所以它和目录里那条汇总带永远不会漂开。样式沿用工作区卡片自己的字面色（`#cfd3d6` / `#adb2b8` / `#8c9299`），不跟主题 token——那张卡片本身是字面暗色绘制的，跟 token 反而会在浅色主题下变成一块异色。摘要是只读的：没有按钮、没有请求、不写状态。没有子智能体时它报的「本会话」一行读的是宿主已经折叠好的 `sessionStats` 投影（`llmMs + toolMs`），与 token 用量在同一份 `projectionValues` 上，所以不需要新请求；会话摘要里并没有 `createdAt`，因此「从建会话到现在的跨度」根本算不出来，只有工作时长。
- 立即弹出：同样不改官方包，也不替换任何导出——`@deepseek-ai/dsh-client-ui-primitives` 那份命名空间是 shell 用 `Object.freeze` 造出来发给每个 bundle 的，往它上面写 `HoverCard` 是一次**静默空写**（上一版实现就是这么失效的：写没生效，返回的却是「装上了」）。改在**定时器**上：`installInstantHover(window, 0)` 同时包住 `window.setTimeout` 与 `window.clearTimeout`。开卡那支认「回调正文里出现 `("open")`（原语开卡就是 `() => { setPhase("open") }`，压缩后是 `()=>{D("open")}`）且延迟大于 0」，压成 0，其余参数原样透传；宽限那支认「回调先把某个 ref 写 null、紧接着调用另一个 ref」（原语 `usePointerGrace` 是 `setTimeout(() => { timerRef.current = null; closeRef.current(); }, 200)`，压缩后是 `setTimeout(()=>{n.current=null,o.current()},200)`），延迟不写死、只认这个属性名形状——压缩器不改属性名，所以官方改毫秒数它照样命中。记下的宽限在**开新卡时**就地提前执行（先 `clearTimeout` 再照原样调用回调），新旧两卡因此落在同一次 React 提交里：旧的先卸载、新的再挂载。`clearTimeout` 也包着，所以卡片自己取消掉的那次宽限（例如鼠标又移回原来那行）不会被背后补一刀，已经自然到点的也不会补第二刀。侧边栏会话行的卡片是 compact 变体，`close()` 直接进 `"closed"`、没有淡出，所以「当场收掉」就是真的当场消失。幂等（两个包装都带 Symbol 标记，二次安装直接返回 null）；装不上（缺 `clearTimeout`、只读、写入即抛错、写进去没生效）只报一条 console 警告、把已经写下的那一半放回去并保留官方延迟，绝不拖垮插件；卸载只在两个定时器都仍是我们那层时才各自还原，不掀掉后装的层。

- 失败原因：宿主半边另有一支 `ctx.inject(['sessionQuery'], …)` 里的 `agent/pre-step` 监听（waterfall 事件）。它先 `await next()` 拿到本步的决定，只在「决定是 `enter`、消息里确实有一条 `source.kind === 'subagent-settled'` 且尚未补注的通知、且开关为真」时才去读**那个子会话**的日志（`sessionQuery.readSession`），折叠出最后一条 `turn/end` 的 `reason`（`kind`、`error.code`、`error.message`），以一条文本块**附在同一条通知消息上**：不改写原消息（journal 里那条仍是宿主写的原文，回看历史不会看到插件的字），只改进入这一步的那份副本。放在同一条消息里而不是另发一条，是因为两者必须同步到达——「失败了」和「为什么」隔几步才到，父智能体早就按猜测重新规划过了。已补过的通知由那条补注自己认出来（正文含 `[subagent-mgm]` 即跳过），不会跨步重复追加。整支监听都在 try/catch 里，异常一律还原成原决定：钩子抛错会连累父智能体这一步，比少一行诊断严重得多。这一支不依赖 `webServer`，没有 HTTP 载体时照样工作；没有挂 `sessionQuery` 时它安静地不生效（`ctx.inject` 等不到依赖就不注册）。

## 已知边界

- 「跟随自动打开」只覆盖当前会话的直接子智能体；更深的层级请用目录里的「在侧边栏打开」按钮。关闭不受此限：任何会话里已开的面板，只要插件见过它的子智能体在运行，结束时都会关。
- 刷新页面后从侧边栏布局里恢复出来的面板，如果其子智能体在刷新前就已经结束，插件不会去关它——它没看见那个子智能体运行过，只能当作你手动打开的面板。
- 自动打开的面板与用户自己打开的面板是同一个标签，因此关闭时两者无差别。
- 需要官方子智能体 UI 的聊天资源（`dsh-resource://subagentchat/...`）；若该提供者不可用，插件只保留目录倒序，并在控制台报错而不是反复重试。
- 能力面板里的人格只有三种结局：委派记录里写了（最常见）、从系统提示差分恢复、或者判定为「恢复不了」而显示为空。差分只认 persona 槽位——差异必须从双方首次系统提示的第 3 行开始，否则宁可显示为空，也不把别的 section 当成人格。没有委派人格的子智能体，恢复到的往往是宿主按模型生成的那一行，面板会明确标注，不要当成「谁指派的人格」。
- 能力面板里的工具是**最后一次请求**的清单：会话中途换预设或工具集后，显示的是当前生效的那一份，不是委派当时的那一份。SKILL 清单同理，是「此刻」这个会话可见的技能——但**只有这次委派的工具面里确实有 `skill` 时才会列出来**：委派时没给它 `skill`（allow 里没写、deny 里写了，或最后一次请求的工具清单里就没有），这一段只说明它看不到任何技能，因为技能目录只发给手里有 `skill` 工具的智能体。
- 过滤只能筛客户端**确实拿得到**的字段：名字、标题、工作目录、运行状态、模式。**按模型或预设筛选做不到**——会话列表给浏览器的那份摘要里没有模型/预设字段（预设只在会话头里，投影里也没有模型），模型只能靠上面那条按需批量接口读出来，所以它用于「按模型看用量」，不参与筛选。
- 汇总与过滤都只覆盖**已经加载进这一屏的行**：目录是按需分层的，没展开过的下级不在其中，条上的数字是「已加载」而不是「全部」。要给全部子智能体算总量，得先把目录展开到那一层。
- 计进合计的只有**当前这一屏的会话自己**（token 与缓存桶进合计），不是「整棵祖先链」：它就是这个目录挂靠的那个会话，也就是你正在看的那一个。它的活跃耗时没有记录（那边只有子委派的计时），所以「合计」的时长只覆盖真的被委派跑过的那些行，它只贡献 token 与缓存桶；而在子智能体里的面包屑切换器上，计进来的就是那个子会话自己。它的 token 只在会话摘要的投影里，摘要还没到时不显示（不会算成 0）。
- 缓存命中率是**已经计费的那部分提示**的命中率：分母只含未缓存输入 + 缓存读 + 缓存写，输出 token（以及没有投影的行）不进分母。所以它和聊天页底部那一行是同一口径，但和「token 合计」不是同一批数字——合计含输出，命中率不含。缓存读为 0 或整屏都没有用量时不显示这一项，而不是显示 0%。
- 过滤状态在菜单关闭后**保留**（搜索框与筛选片下次打开时仍是原样，一眼可见），想要清掉点控制条上的 ×。
- 悬浮摘要只列**直接子行**（最多 4 个），更深的下级只体现在计数里；它也不含模型分组——模型要读日志，那是目录里那个按需按钮的事。
- 悬浮摘要里的行**不可点**：卡片整块的点击已经被工作区用于复制会话标题，同一张卡里再放导航会互相打架。想打开某个子智能体，用目录里的按钮。
- 官方那行「N 个子智能体运行中」不会被替换掉：它由工作区自己渲染，插件只是在它上方补了一段。因此这两处的「N」含义不同——官方那行是**正在运行**的个数，摘要里的计数是**已加载**的子智能体数。
- 立即弹出与「新卡替旧卡」作用在**共用**的那支开卡定时器与那支指针宽限上，所以侧边栏会话行、工作区分组行以及预览卡会一并立即展开，别的弹出层（如下拉菜单）若正好处在 200ms 宽限里、旁边又弹出一张卡，也会跟着提前收。命中靠的是回调**形状**（开卡那支认正文里的 `("open")`，宽限那支认「ref 写 null 后紧接着调用另一个 ref」这个属性名形状），而不是那个 800ms / 200ms，所以官方改毫秒数也不影响它；代价是形状变了它就安静失效（控制台仍会报安装成功——它确实装上了，只是不再命中）。想恢复官方那 800ms / 200ms：把 `apply` 里那次 `installInstantHover(...)` 去掉即可（`INSTANT_HOVER_OPEN_MS` 就是强制使用的等待毫秒数，改成别的数字也行）。
- 没有子智能体时显示的「总用时」是宿主 `sessionStats` 折叠出来的模型时间 + 工具时间，**不含**排队与等待输入的时间，也不等于「这个会话存在了多久」（会话摘要里根本没有创建时间）。投影还没到、或这个会话什么都没记时，这一项不显示，而不是显示 0。
- 那一行的 token 与命中率同样来自会话摘要的投影：摘要还没到时只显示还剩得下的项；三项都拿不到时整段不出现（与「空会话」表现一致）。
- 失败原因读的是**子智能体自己的日志**，所以只在日志已经落盘时才有内容：它还在写、或者这个 profile 已经清掉了它的日志，补注就只剩「没跑完任何一轮」或「日志不在这个 profile 里」这两句。补注是**给模型看的**（只进父智能体那一步的消息副本），不改写磁盘上 journal 的那条通知，所以回看历史时那条通知仍是官方原文——要人工查原因，看**子智能体自己那个会话页**上的「本轮运行失败」，或读它的日志。
- 补注只处理可继续（continuable）模式的结束通知，因为只有那条路径把失败明细丢掉了；一次性（one-shot）子智能体的失败原因本来就在父智能体收到的工具结果里（`Error: <stopReason>` 加 `Diagnostic: …`），插件不去重复。读取另一个会话的日志走的是宿主 `sessionQuery` 只读接口，与能力面板、模型批量是同一支，插件不写任何会话数据。
