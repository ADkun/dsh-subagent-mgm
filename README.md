# dsh-subagent-mgm

DeepSeek Harness Web UI 插件（bundle）：管理子智能体的目录顺序与右侧栏面板。

## 它做什么

1. **子智能体目录按创建时间倒序**。会话顶部「N 个子智能体」的展开菜单里，最新的子智能体排在最上面；展开的每一层下级目录同样按创建时间倒序。行的内容（状态点、标题、模式、活跃耗时、token 数、在侧边栏打开按钮、键盘导航、悬停展开）与原版一致，只改了顺序。点进某个子智能体会话后，会话顶部那枚**面包屑切换器**（列出父会话的兄弟子智能体）同样被接管，也按创建时间倒序；它旁边保留「这个子智能体自己的子目录」计数入口，行为与原版一致。
2. **跟随子智能体自动开合右侧栏面板**。当前屏幕上这个会话有子智能体在运行时，自动在右侧栏打开它的会话；子智能体结束时自动关闭该面板。
   - 结束时的关闭**不限于当前屏幕上的会话**：子智能体在后台会话里结束，也会把它留在这个会话侧边栏里的面板关掉，切回该会话时不会再看到已经结束的子智能体聊天。
   - 已经存在的子智能体被父智能体再次派活（可继续模式）、重新开始工作时同样会自动打开；若它的面板还开在后台标签里，则把它拎到前台并展开右栏，而不是再开一个。
   - 每次运行只自动处理一次：同一个子智能体连续运行期间不会反复把右栏抢回前台，用户可以自己切走；切换会话再回来也不会重新抢。
   - 用户手动提前关闭：该子智能体本次运行期间不会再被自动打开（跨会话切换同样不会），下次重新运行时会恢复自动打开。
   - 用户手动打开：插件不会去关它，除非该子智能体结束。
   - 打开只处理当前会话的**直接**子智能体；面板打开方式是「已在则复用」，不会为每次自动打开强行新建分栏。
3. **设置页**：设置里多一页「子智能体管理」（排在官方插件设置页之后）。四个开关——
   - 子智能体目录/面包屑按创建时间倒序（关掉即回到官方原顺序）；
   - 子智能体开始运行时自动打开右侧栏面板；
   - 子智能体结束时自动关闭该面板；
   - 把已开在后台的面板拎到前台（关掉就完全不抢焦点，只保证面板已存在）。

   保存会写入本插件的设置文件，可一键恢复默认；刷新后仍然生效，页面上同时显示当前生效值与设置文件路径。
4. **查看某个子智能体「有什么」**。目录里每一行多一个证件卡按钮，点开该行的能力面板（菜单会临时加宽），四段只读信息——
   - **这份工作是什么**：模式（可继续 / 一次性）、此刻是否在运行、唤醒方式、预设、它这一次运行所用的模型与推理档位、工作目录、层级深度、父会话、创建时间，以及委派时设定的**工具过滤**（allow / deny）；
   - **工具**：它在最后一次请求里实际拿到的工具清单与描述，每个工具可展开看它的参数 schema；
   - **SKILL**：这个会话（它的预设 + 工作目录）当前可见的技能清单，并标出哪些是「仅智能体可调用」；宿主没挂技能注册表时会明说，而不是显示成空；
   - **人格**：委派记录下来的 persona（权威）；没有记录时，由它的系统提示与**该父会话首次组成时**的系统提示做差分恢复，并注明这是推断；如果恢复到的这一行其实是宿主按运行模型填进人格槽位的，会标注「按运行模型生成」。

   内容全部由宿主只读推导（浏览器读不到别的会话的日志）。面板有返回按钮，Esc 退回目录，加载失败可重试。
5. **在目录里找子智能体，并看清这一屏的用量**。展开菜单顶部多了一行控制条和一条汇总带——
   - **搜索与筛选**：按名字 / 标题 / 工作目录做大小写不敏感的文本匹配，另有「全部 / 已结束 / 仅一次性」两个筛选维度（可叠加）。命中行会连同它的祖先一起显示（祖先只是路径，否则你就看不到它挂在谁下面），并且层级自动展开、不可再折叠；过滤期间展开箭头不再可点，避免「展开了但看不到东西」。什么都没命中时给一句话，而不是一片空白。
   - **汇总**：分两行摆，各自换行也不会互相挤压——上面一行是计数（这一屏**已加载**的行数、其中在运行的个数，以及拿不到投影的「N 个没有用量数据」），下面一行是用量（token 合计、**缓存命中率**、活跃耗时合计，悬停都给精确值）。**当前这一屏的会话自己也算进合计**，并在合计里点名它的份额（「合计 1.2M（本会话 320K）」），悬停给出它自己的缓存读 / 缓存写 / 提示 / 未命中：它不在目录里，所以不算一行、计数不变，但它的 token 和缓存桶和这些子智能体花在同一处。拿不到投影的行不会算成 0。
   - **缓存命中**：命中率 = 缓存读 / 提示侧用量（提示侧用量 = 未缓存输入 + 缓存读 + 缓存写，**输出 token 不算**），与聊天页底部的口径一致。命中不足 100% 时不会四舍五入成 100%（99.99% 就显示 99.99%），悬停给出「缓存读 / 缓存写 / 提示 / 未命中」的精确拆分。整棵树**先按桶求和再取比值**，所以它是「这一屏的真实命中率」，不是各行命中率的平均；没有用量的行不进分母，一行用量都没有时干脆不显示这一项。
   - **按模型分组**：点一下按钮才去读——模型只写在各自会话的日志里，浏览器拿不到，所以这是一次**按需**的只读批量请求，读完就按模型分好组（每个模型一行：token 合计、该组的缓存命中率、命中行数；由委派指定、还没跑过的行标注出来）。读不到就报错并可重试，不假装成「未知模型」。这一屏的会话自己也在被统计的节点里（它有自己的模型），所以某个模型行末尾的 × 计数把它算作一个。

## 实现要点

- 浏览器半边通过 `window.__ModuleLoader__.load({ id: 'dsh-subagent-mgm', factory })` 注册，`exports.inject` 声明所需服务：`sessions`、`uiWorkspace`、`slots`、`locale`、`sidebarRight`。
- 目录：以 list slot 的 shadow 机制（同一 `id`、更低 `priority` 生效）接管 `conversation.session.header.actions` 里的 `subagent-catalog` 座位，复用官方 `@deepseek-ai/dsh-client-ui-subagent` 的标记结构、样式与行为，类名前缀改为 `smgm-`，文案注册在自有命名空间 `subagentMgr`。
- 面包屑：子智能体会话的标题位是 single slot `conversation.session.header.lineage`，官方在这里放的就是那枚兄弟切换器。single slot 没有 `id` 可复用，只能用更低的 `priority: -1` 抢在官方（priority 0）前面，否则进入子智能体后会退回原版顺序。
- 面板：订阅 `ctx.sidebarRight.mounted`、`ctx.sidebarRight.openTabs`、`ctx.sessions.list`、`ctx.uiSession.sessionStatus`，每次变更后先按「`openTabs` 里每个会话的已开标签 ∩ 运行状态」关掉已经结束的子智能体面板（对屏幕上的会话和后台会话一视同仁），再按「当前会话的目录 ∩ 运行状态 ∩ 已打开标签」对账自动打开；标签地址形如 `dsh-resource://subagentchat/session/<child>?parent=<parent>&mode=<mode>`，与官方子智能体聊天资源提供者一致。运行态记录（是否见过它运行、是否被用户手动关过）按子会话 id 全局记账、跨会话切换保留，只有「本次已拎到前台」和投影重试记录会在切换会话时重置。
- 设置页：在官方 `settings.section`（list slot，scope root）注册一页，`id: subagent-mgm`、`order: 37`、`label: () => t('settings.nav')`。开关存在浏览器侧的订阅式 store 里，目录排序和面板对账各自在每次计算时读一次，所以改完立即生效，不需要重启，也不需要刷新页面。
- 宿主半边：用 `ctx.inject(['webServer'], …)` 注册 `prefix` 路由 `/api/subagent-mgm`，其 `/settings` 支持 GET / POST / DELETE；设置写入 `<DSH_PROFILE_DIR|DSH_HOME|~/.dsh>/subagent-mgm.json`（先写临时文件再 rename 原子替换，权限 0600），字段优先级为「已保存文件 → 本行 Config → 内置默认」，行默认值写在本 bundle 的 `cordis.patch.yml`。路由沿用与 connection 服务相同的同源栅栏：没有认证的非浏览器客户端收到 401，跨站 Origin / 伪造 Host 收到 403。
- 能力面板：同一前缀下还有 `/face?sessionId=…&parent=…`（GET，只读）。宿主用 `sessionQuery.readSession` 读该会话的持久日志，折叠出首个 `subagent/descriptor`、**最后一次** `request/header` 的工具与模型、以及人格；技能来自可选的 `sessionSkillCatalog.list`（服务缺失 → `unavailable`，抛错 → `error`，都不影响其余字段）。人格三级来源：descriptor 里的记录（权威）→ 与父会话系统提示做行级差分（公共行前缀 ≤ 2 行才认，因为 persona 槽位紧跟 harness 身份行；恢复到的通常是宿主按模型生成的那一行，用返回体里的 `generated` 标注）→ 都没有就为 `null`。差分只比**双方日志里的第一份**系统提示：会话中途换模型会重写人格槽位，那份晚到的组成与「这次委派给了它什么」无关——真实日志里确实出现过，按最后一份比会凭空造出人格。父会话 id 优先取会话头里的 `parentSession`，前端再把当前打开的会话作为 `parent` 提示兜底（老日志没有该字段时仍能恢复）。客户端只渲染返回体，自己不读日志。
- 过滤与汇总：全部是**客户端行为**，只在这一屏已加载的目录投影上做，不读任何日志、不发任何请求。过滤是每层独立裁剪（子层是自己按 `catalogOf(childId)` 现取的，不是从父层继承），谓词是「自身命中，或任一已加载的后代命中」——所以祖先会作为路径留下，**也计入汇总**：汇总说的是「屏幕上这些行」，因此按「未运行」筛出来的结果里仍可能报 1 行在运行（那是被留下的祖先）。**当前这一屏的会话本身也走同一套记账**（`catalogTotals` 里只有一个内部折算函数，行与它共用，两边不会漂开）：它不占行数，但 token 与缓存桶进合计；去留也由同一个过滤谓词决定，于是「仅一次性」会把它排除（它不是委派），状态筛选只在它自己匹配时留下它，而它一旦被留下就不会再作为行被重复计数（先记进去重集合）。没装宿主新半边时按模型分组会显示读取失败。缓存命中率也在这批行上算（含这一屏会话），但**先按桶求和再取比值**：比例之和 ≠ 比例的平均，逐行算好再相加会让整屏数字和单份日志的口径漂开；没有用量的行不进分母，分母 ≤ 0 时返回 `null`（这一项不显示），部分命中**朝下取整而不是进位到 100%**——99.99% 就是 99.99%。
- 模型批量：`GET /api/subagent-mgm/models?sessionIds=a,b,c`（GET，只读）。每个 id 过一次 `SESSION_ID` 校验、去重、上限 64 条（超了 400），逐 id 读一次 `sessionQuery.readSession` 折叠出「委派指定的 `agentModel`（descriptor）」与「这一轮实际在跑的 `model`（最后一次 `request/header`）」，外加模式与预设。**单条失败只影响那条**：日志不存在 → `state: "missing"`，读失败 → `state: "error"` 带上原因，整批照样 200。客户端按 `totals.nodes` 里出现的 id 发起，拿回来按 sessionId 归档；用户在条上改了筛选后再点一次就重新读。

## 自检

`node verify.mjs`（随包保留，不参与 bundle 装载）：从 `client.js` 原文抽出 `sortNewestFirst`、`chatAddress`、`panelChildId` 与 `startSubagentPanels`，用假上下文驱动对账状态机，覆盖排序、面板身份解析，以及“运行即开 / 结束即关 / 用户关掉不再抢回 / 父智能体再次派活重新打开 / 已开面板只拎到前台不重复开”等断言；第二组专门覆盖“子智能体在后台会话里结束”——面板照关、切回该会话看不到残留、屏幕上没有会话（如设置页）时同样关，而用户手动为已结束子智能体打开的面板不受影响；第三组是针对面包屑半边的**静态**接线检查（shadow 优先级、兄弟切换器与自身计数入口、展开时补拉子目录、两侧字典与样式类齐全）。另有针对**能力面板**的两组：静态组检查行内按钮、加宽菜单、dialog 分支、两个字典里每个 `face.*` 键、四个分区的四态文案与 4000 字符截断；行为组用假日志直接驱动 `/face` 路由，覆盖 400 / 404 / 405 / 403、字段折叠（工具取最后一次请求、schema 原样传递）、人格的三种来源（委派记录 / 从系统提示恢复 / 不可恢复）、父会话被中途重组时不得凭空造出人格，以及技能注册表缺失或报错时的降级。第四组针对**搜索/过滤与汇总**：静态检查接线（控制条在树上方、树的 role 与键盘处理分居两层、过滤期间不可折叠、过滤沿递归下传、模型批量只按需发起），行为检查把 `filterActive` / `entryMatches` / `subtreeMatches` / `catalogTotals` / `modelOf` / `groupModels` 从原文抽出来，用一棵固定目录树（含嵌套的一次性子智能体、没有投影的行、指回祖先的环、同一父下重复列出的行）验证：命中祖先连带祖先一起出现、祖先也计入汇总、无用量算「未知」而不是 0、环不会无限展开、重复行只算一次、没答复的 id 归入「未知模型」且单独计数。第五组直接驱动 `/models` 路由处理器：顺序与去重、空参数 / 非法 id / 超过 64 条各自的 400、POST 405、跨站 403、未挂 session-query 时 503，以及「一条日志读不出来只让那一条变成 error，整批仍然 200」。缓存口径单独成组：分母只含提示侧用量（输出 token 再多也不进分母）、`null` 的三种成因（分母为 0、分母缺失、缓存读为 0）、部分命中不得进位成 100%、整批与每个模型分组都是先求和再取比值、没有用量的行不加分母，以及汇总带确实分成「计数」「用量」两行。父会话计入统计单独成组：用同一棵目录树加一份「树所依附的会话」的摘要，行为上验证它进合计、进缓存桶、排在行之前、只算一次，并且被**同一过滤规则**决定去留（文本/状态命中它才留，「仅一次性」必然排除它）；静态上验证它和行走同一个折算函数、不会作为行重复计数、无用量时那两行仍然各自只有一行。共 295 项：除上述行为断言外，还包括设置页开关的行为与静态接线，以及直接驱动宿主路由处理器的 GET / POST / DELETE、越权与方法/字段校验、字段优先级链（临时目录里跑，不碰你自己的设置文件）。页面渲染本身是 React/DOM，只做静态接线检查，不驱动浏览器。

## 安装 / 卸载

安装（在 DSH 里让 agent 执行，或直接用插件管理器的 bundle 安装）：

```
plugin_manager action: install_bundle target: D:\dsh\dsh-subagent-mgm
```

安装后刷新页面生效；若改动的是宿主半边（`index.js` / `cordis.patch.yml`），需要重装 bundle 或重启 dsh 才会装载（只改浏览器半边 `client.js` 刷新即可）。卸载用插件管理器的 `remove_bundle`，目标 `dsh-subagent-mgm`；卸载后官方原版目录立刻恢复（本插件只是 shadow 了那个座位，没有改动官方包）。

## 已知边界

- 「跟随自动打开」只覆盖当前会话的直接子智能体；更深的层级请用目录里的「在侧边栏打开」按钮。关闭不受此限：任何会话里已开的面板，只要插件见过它的子智能体在运行，结束时都会关。
- 刷新页面后从侧边栏布局里恢复出来的面板，如果其子智能体在刷新前就已经结束，插件不会去关它——它没看见那个子智能体运行过，只能当作你手动打开的面板。
- 自动打开的面板与用户自己打开的面板是同一个标签，因此关闭时两者无差别。
- 需要官方子智能体 UI 的聊天资源（`dsh-resource://subagentchat/...`）；若该提供者不可用，插件只保留目录倒序，并在控制台报错而不是反复重试。
- 能力面板里的人格只有三种结局：委派记录里写了（最常见）、从系统提示差分恢复、或者判定为「恢复不了」而显示为空。差分只认 persona 槽位——差异必须从双方首次系统提示的第 3 行开始，否则宁可显示为空，也不把别的 section 当成人格。没有委派人格的子智能体，恢复到的往往是宿主按模型生成的那一行，面板会明确标注，不要当成「谁指派的人格」。
- 能力面板里的工具是**最后一次请求**的清单：会话中途换预设或工具集后，显示的是当前生效的那一份，不是委派当时的那一份。SKILL 清单同理，是「此刻」这个会话可见的技能。
- 过滤只能筛客户端**确实拿得到**的字段：名字、标题、工作目录、运行状态、模式。**按模型或预设筛选做不到**——会话列表给浏览器的那份摘要里没有模型/预设字段（预设只在会话头里，投影里也没有模型），模型只能靠上面那条按需批量接口读出来，所以它用于「按模型看用量」，不参与筛选。
- 汇总与过滤都只覆盖**已经加载进这一屏的行**：目录是按需分层的，没展开过的下级不在其中，条上的数字是「已加载」而不是「全部」。要给全部子智能体算总量，得先把目录展开到那一层。
- 计进合计的只有**当前这一屏的会话自己**（token 与缓存桶进合计），不是「整棵祖先链」：它就是这个目录挂靠的那个会话，也就是你正在看的那一个。它的活跃耗时没有记录（那边只有子委派的计时），所以「合计」的时长只覆盖真的被委派跑过的那些行，它只贡献 token 与缓存桶；而在子智能体里的面包屑切换器上，计进来的就是那个子会话自己。它的 token 只在会话摘要的投影里，摘要还没到时不显示（不会算成 0）。
- 缓存命中率是**已经计费的那部分提示**的命中率：分母只含未缓存输入 + 缓存读 + 缓存写，输出 token（以及没有投影的行）不进分母。所以它和聊天页底部那一行是同一口径，但和「token 合计」不是同一批数字——合计含输出，命中率不含。缓存读为 0 或整屏都没有用量时不显示这一项，而不是显示 0%。
